## 1. 事業コンセプト

歯科医師によるオンライン診療を受けた患者に対して、ホームホワイトニング材をオンライン販売し、自宅へ郵送するサービスを構築する。
既存歯科医院とは切り離した独立ブランドとして運営する。
基本コンセプトは、
「来院せず、オンラインで歯科医師に相談し、自宅で医療ホワイトニングを始められる」
こと。
一般的なECサイトとして商品を自由販売するのではなく、
患者登録 → 事前スクリーニング → 歯科医師によるオンライン診療 → 適応確認 → 購入許可 → 商品購入 → 発送
という流れを基本とする。
MVPではカスタムホワイトニングトレー製作・自宅印象キット等は扱わない。
まずは、
オンライン診療＋Opalescence販売・郵送
に集中する。

## 7. 利用年齢

本サービスは、
18歳以上のみ利用可能
とする。
18歳未満はオンライン診療予約・商品購入へ進むことができない。
患者登録時に生年月日を入力させ、システム側で年齢を自動判定する。
18歳未満の場合は、
「本サービスは18歳以上の方を対象としています。」
等を表示して登録を終了する。

## 8. 登録時スクリーニング

オンライン診療へ進む前に、最低限の事前スクリーニングを行う。
確認項目：

* 妊娠中または授乳中ではない
* 無カタラーゼ症と診断されたことがない
* 現在、強い知覚過敏の症状がない

患者には、
「以下の内容を確認しました」
という形式でチェックさせる。
すべての条件を満たした患者のみ、登録・オンライン診療へ進むことができる。
条件を満たさない場合は、
「安全上の理由から、本オンラインサービスをご利用いただけません。症状や状態については、かかりつけの歯科医師・医療機関へご相談ください。」
等を表示する。

## 9. スクリーニング情報の保存方針

妊娠・授乳、無カタラーゼ症、知覚過敏などの個別回答は健康・医療に関連する情報となるため、
ECデータベースには詳細な回答を長期間保存しない。
EC側では原則として、
screening_passed = true / false
のように、
スクリーニングを通過したかどうか
のみを保持する設計を優先する。
詳細な診療情報をECシステムへ蓄積しない。

## 実装時の変更履歴

### 2026-08-23: ログイン方式を「メール＋ワンタイムコード」→「メール＋パスワード」に変更

**該当項目**: 11項（ログイン方法）、30項（MVPで自作するもの）

**変更内容**: マスタープロンプトでは「パスワードを作らせない、メール＋ワンタイムコード」方式を想定していたが、実装検討の結果、**メールアドレス＋パスワード方式**に変更した。

**理由**:
1. 16項の「今すぐ診療」機能は、患者の購買意欲が高い瞬間にその場で診療〜購入まで完了させることを狙いとしている。ログインのたびにメールの到着を待つ設計は、この瞬間の離脱リスクになると判断した。
2. パスワードマネージャー（ブラウザの自動入力、iPhoneのパスワード機能等）を使えば、メール確認なしで一瞬でログインできる。
3. Supabase（採用しているバックエンド基盤）の初期設定では、独自のメール配信サービス（カスタムSMTP）を設定しない限り、確認メールの本文をカスタマイズできない制限があり、「6桁のコードを表示する」体験の実現にはメール配信サービスの追加導入が必要と判明した。

**補足（UXへの影響について）**: パスワードなし方式を避けた狙い（パスワード忘れ・再発行対応を減らす）とのトレードオフについて事業オーナーと協議した結果、以下の理由で妥当と判断した。
- ログイン状態はブラウザに保存されるため、毎回のサイト訪問でメール確認・パスワード入力が必要になるわけではない（初回・ログアウト後・別端末利用時のみ）。
- 本サービスは再購入までの間隔が数ヶ月単位と想定される（29項の購入比率想定より）ため、パスワード方式でもパスワードを忘れられるケースは相応にあり、その場合は結局メール経由のパスワード再設定が必要になる。ワンタイムコード方式との体験差は、当初想定ほど大きくないと判断した。

**現在の実装**: Supabase Authの標準機能（`signUp` / `signInWithPassword`）を使用。会員登録確認・パスワード再設定は、いずれもSupabase標準のメールリンク（デフォルトテンプレート、カスタムSMTP不要）で対応している。将来、Resendなどの外部メール配信サービスを導入するタイミングで、ワンタイムコード方式への切り替えを再検討してもよい。
